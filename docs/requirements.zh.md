# 需求

模式管理必须做到什么，以及每一部分是怎么验证的。需求只在这里写一份：一个功能在 `.scratch/<功能>/` 下的需求稿，做完后并进这里。用词以 [GLOSSARY.zh.md](../GLOSSARY.zh.md) 为准；设计背后的理由见 [docs/adr/](adr/)。

## 给谁用

想让 DSH 的 Agent 模式贴合自己工作的人：要一个不能跑命令的模式、换一份系统提示词、把工具描述写得更清楚，或者让某些技能只在部分模式里加载。在 DSH 里，这些都要手动一行行改 profile 的 YAML，面对的是插件名而不是能力。

## 目标

- 看清每个模式能做什么，按能力开关，而不是按插件。
- 编辑每个模式的系统提示词和工具描述，有历史记录，也能回到内置原文。
- 按模式开关技能、固定版本，新建和导入技能。
- 从模板或复制来新建模式。
- 让改过的模式跟上 DSH 的内置更新。

## 不做的事

- 不改 DSH 安装目录里的任何文件：所有改动都是 profile 的覆盖配置（[ADR 0001](adr/0001-edits-are-profile-overrides.zh.md)）。

## 约束

- 现有的每项功能都保留，Skill 管理出现后也一样。
- 它和 Skill 管理各自独立，也能一起用；两个都装时，按模式的技能设置以模式管理为准。
- 卸载后，它改过的每个模式都照常能用。
- 页面跟随 DSH 的语言，所有文字都有中英文。
- 页面里能检查新版本并升级插件。
- 页面绘制出错时显示错误原文和「重新加载」，不会是一片空白。
- 支持 Windows、macOS、Linux，Node `^22.19.0 || >=24`。
- README 和市场介绍只写验证过的事。

## 功能

验证记录里的检查，都是在装进隔离 `DSH_HOME` 的 DSH 上做的；发给模型的请求用 DSH 自带的本地假模型和一个记录请求的代理检查。

### 模式列表

**验收标准**

- 每个模式是一张卡片，显示名称、说明、能力、状态和操作（用它新建会话、设为默认、复制、查看配置、编辑信息、恢复内置、删除）。
- 模式需要处理时，卡片显示一条提示，带一个能解决它的按钮。

### 能力

**验收标准**

- 每个模式的每项能力一个开关；打开时恢复成内置模式里的样子，关闭时关掉它包含的所有插件。
- 只开了部分插件的能力标为「部分开启」；模式里没有对应插件的能力不显示。

**验证记录**

- 「只读调研」模式的工具列表里，没有任何写文件、编辑或终端工具。

### 提示词

**验收标准**

- 每个模式的系统提示词都能编辑：输入时检查变量，能预览完整提示词，有结尾提示词和高级开关。
- 每次保存记一个版本（最多 30 个），可以载回；提示词能以 `.md` 导入导出。
- 没保存的修改在刷新页面后仍在；编辑期间提示词在别处被改，不会不经确认就覆盖。
- 恢复内置提示词前会先确认。

### 即时生效和对话中修改提示词

**验收标准**

- 打开「即时生效」后，保存的提示词从下一步起作用于这个模式里正在运行的会话（[ADR 0003](adr/0003-saved-prompts-reach-running-sessions.zh.md)）。
- 允许对话中修改时，模型通过 `mode_prompt` 读取和修改提示词，每次修改都先请求批准。

**验证记录**

- 即时生效后，同一会话的下一步请求就带上了新提示词。
- 模型调用 `mode_prompt` 时界面弹出审批，批准后下一步请求就带上了修改后的提示词。

### 工具描述

**验收标准**

- 模式注册的任何工具的描述都能改写，可以只改一个模式，也可以一次改多个；工具的名称和参数从不改变。
- 可以恢复一个工具、一个模式、勾选的所有模式，或全部的内置原文，每种都先确认。
- DSH 升级后内置描述变了的工具会被标出，修改继续生效。

**验证记录**

- 改过的模式新建会话后，发出的请求里恰好只有被改的工具带着新文字；正在运行的会话在下一次请求就带上之后的修改；恢复之后下一次请求又是内置原文。在 `0.2.0-rc.2` 和 `0.2.1-rc.1` 上都检查过。

### 按模式管理技能

**验收标准**

- 每个技能可以按模式或在所有模式里开关，一个模式可以固定在某个技能的保存版本上。
- 版本可以带备注保存、查看、恢复和删除；编辑或恢复前先保存当前文件；正被使用的版本不能删除。
- 开关和固定版本从不移动技能文件；`node_modules` 里的技能不能编辑或恢复。

**验证记录**

- 在新建的 Standard 会话里，被关闭的技能不在目录中；固定版本的技能显示保存版本的描述，加载到的也是保存的正文，而文件里是编辑后的内容；在所有模式里关闭某个技能后，运行中会话的下一次请求里它就消失了；恢复版本前会先保存编辑后的文件，然后文件回到原来的内容。在 `0.2.0-rc.2` 和 `0.2.1-rc.1` 上都检查过。

### 新建和导入技能

**验收标准**

- 新技能写到 `~/.dsh/skills` 或 `~/.agents/skills`，只在为它选的模式里开启。
- Codex、Claude Code、Claude Code 插件或指定文件夹里的技能可以复制导入；重名时可以改名导入，或在保存版本后覆盖。
- 导入的技能来源变了会被标出，可以重新导入。

**验证记录**

- 在 `0.2.1-rc.2`（npm）和 `0.2.1-rc.1`（源码）上，用放在 Codex、Claude Code、Claude Code 插件和普通文件夹里的示例技能检查过：导入列表显示的状态正确；需要改名的技能用新名字复制，副本里的 `name` 也改写了；每个模式的技能目录（`skills.snapshot`）都列出了新技能；新建时不勾选的模式里它是关闭的；来源改动后会被标出来，重新导入前会先存一个版本。
- 还没用模型请求验证：正在运行的会话拿到新技能。

### 全部插件

**验收标准**

- 模式里的每个插件都能搜索、开关（按环境切换的插件可选「自动」「开」「关」）、逐个恢复和查看详情。

### 新建模式

**验收标准**

- 可以从「开发」「写作」「聊天」「只读调研」模板新建模式，或复制一个模式；每个模板带一份跟随界面语言的初始提示词。

### 跟上 DSH 升级

**验收标准**

- DSH 升级后，改过的模式会提示「内置模式有更新」，列出上游改了什么，确认后合并进来并保留用户的修改（[ADR 0002](adr/0002-built-in-updates-are-merged-three-ways.zh.md)）。
- 模式里有插件加载失败时，一键关掉失败的插件。
- 删除自定义模式前，先说明有多少打开的和保存的会话在用它。

### 卸载后模式照常能用

**验收标准**

- 插件删除后，它改过的每个模式都还能加载、能开会话。
- 重新安装后所有设置都回来。

**验证记录**

- 在 `0.2.1-rc.2` 上给标准模式设了技能设置、即时生效并改了提示词、`mode_prompt` 和一条工具描述修改。`dsh plugin remove` 并删掉插件文件后，标准模式仍在模式列表里，能新建会话，本插件的行都已关闭，组装出的提示词里改过的文字出现一次。重新安装后所有设置都回来了。
- 0.8.0 保存的标准模式覆盖在第一次启动时补上了条件。没有这些条件时，同样的卸载会让标准模式从模式列表里消失，新建会话报 `agent-preset/invalid`。

### 插件自身的更新

**验收标准**

- 有新版本时页面会提示，用户确认后通过 DSH 的插件管理器安装（[ADR 0004](adr/0004-plugin-updates-itself-through-dsh-plugin-manager.zh.md)）。
- 只提供 `latest` 版本，压缩包地址必须是回答查询的那个源上本包的文件。
- 自动检查可以关掉；本地开发安装从不检查。

**验证记录**

- 一份标成 `0.5.0` 的构建，用真实的 npm 仓库检测到最新版本，并通过 DSH 的安装器升级。依赖记成仓库的压缩包地址，插件保持启用；`0.2.0-rc.2` 上安装器要求重启，`0.2.1-rc.1` 上当场替换插件。
- 在 Plugins 页面里用同类安装方式升级，也检查过重启之后的状态：升级前建的自定义模式仍然可用。安装失败时清单、锁文件和文件保持原样。
- npm 和国内镜像返回的最新版本信息都能通过压缩包地址的校验。开关、手动检查和本地开发安装都在页面里检查过。

### 页面出错时

**验收标准**

- 页面绘制时出错，显示错误原文和「重新加载」按钮，点了重新加载页面。
